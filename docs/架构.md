# dock 架构

一份写给"想拿去自己用"的人的说明。讲这个项目由哪些部分组成、
数据存在哪里、怎么改成自己的。

---

## 一句话

**一个壳，加若干个小工具。** 壳负责首页、路由、存储和 PWA 那些事，
工具只管自己那一块。加一个工具是加一个文件，删一个是删掉一行。

仓库里有两套外观，共用同一个内核：

- **根目录那套**：图标网格首页，通用外观，`apps/` 下放工具
- **`skins/orange/`**：一套完整的皮肤（明日方舟夏活同人），四个板块挂在
  一条公路上的四个信封里

两套是并列关系，不是新旧关系。挑一套用就行。

## 数据存在哪里

**所有板块都不直接碰 `localStorage`，也不直接 `fetch`。** 它们只跟一个
存储对象说话，这个对象是谁，由配置一行决定：

```js
storage: 'local'                      // 存在这台设备的浏览器里，不需要任何后端
storage: 'api', api: { base: '/api/dock', token: '…' }   // 存到你自己的服务器
```

两种实现在 `core/storage.js` 里，各自提供**同样六个方法**：

| 方法 | 做什么 |
|---|---|
| `list(app, coll)` | 取一组记录 |
| `add(app, coll, rec)` | 加一条 |
| `remove(app, coll, id)` | 删一条 |
| `get(app, key, 默认值)` | 取一个小设置 |
| `set(app, key, value)` | 存一个小设置 |
| `dump()` / `restore()` | 整份导出 / 导入 |

**同一份板块代码在两种模式下都能跑**，这是这个项目最要紧的一条约定。
公开版发的是 `local`，所以 clone 下来就是个能用的东西，不是一道配置作业。

### 选 `api` 的话，服务器要实现什么

`ApiStore` 把六个方法映射成这几条路径（`base` 是你配的前缀）：

```
GET    {base}/{app}/{coll}              → 记录数组
POST   {base}/{app}/{coll}              → 新增，回传带 id 的那条
DELETE {base}/{app}/{coll}/{id}         → 删除
GET    {base}/{app}/settings/{key}      → { "value": … }
POST   {base}/{app}/settings/{key}      → { "value": … }
```

配了 token 的话，会作为查询参数 `?token=…` 附在地址后面 —— 那是这套代码
最初那个部署的做法，你的服务器要用请求头，改 `ApiStore._req` 一处就行。

`app` 是板块名（`calendar` / `dates` / `ledger` / `todo`），`coll` 通常是
`items`。

### 一句提醒：这不是账号系统

`storage: 'api'` 解决的是"数据存我自己的服务器"，**不是"每个人有自己的账号"**。
没有注册、没有登录、没有多用户隔离，`ApiStore` 全程只带一个 token。

真要做成多人各看各的，得在服务器那边加用户表，并把 token 换成登录态。
这个仓库有意没往那个方向走 —— 一旦有了账号，就得替别人的数据负责。

## 公开版和私有版

**一套代码，两种活法。** 分界只有一个文件：

- `skins/orange/config.js` —— 公开版配置，提交进仓库，纯本地、示例数据
- `skins/orange/config.local.js` —— 你自己的，被 `.gitignore` 挡着

有本地配置就整份覆盖同名字段，没写到的自动用公开那份，**不用整份照抄**：

```js
// config.local.js
export default {
  storage: 'api',
  api: { base: '/api/dock', token: '…' },
  moodApi: '/api/mood',
  queueApi: '/api/dock/reminders',
  queueToken: '…'
};
```

这样，你的数据、接口地址、token 都不会跟着代码走出去。

### 配置项

| 字段 | 作用 | 公开版 |
|---|---|---|
| `storage` / `api` | 四个板块的数据存哪儿 | `local` |
| `panels` | 四个站点的 id、中文名、英文名 | 日历/倒计时/账本/清单 |
| `panelTitle` | 板块顶上那行英文标题显不显示 | `false` |
| `stopIcons` | 四个站点各用哪张图 | 四个信封 |
| `moodApi` / `moodPerson` / `moodToken` | 日历的随笔存哪儿 | `null`（存本地） |
| `cycle` / `cycleLength` | 经期那一层要不要存在 | `false`（连代码都不跑） |
| `pushApi` / `pushKey` / `pushToken` | Web Push 那条路 | `null` |
| `queueApi` / `queueToken` | 交给现成闹钟的那条路 | `null` |
| `ledgerCats` | 账本的分类和图标 | 五类 |
| `dateTags` / `tagStyle` | 倒计时的标签和贴纸 | 八个 |
| `defaultDates` | 头一次打开时自带的日子 | 两个 |
| `sampleTodos` | 头一次打开时自带的清单 | 五条 |
| `decoLayout` | 首页拼贴的默认排版 | 五片 |
| `decoEdit` | 首页那支排版铅笔显不显示 | `false` |

## 四个板块

**日历。** 一天一格。左上角一圈细环是那天清单的完成度，数字底下垫的形状
是纪念日（星）和写了随笔（云），下面那条是倒计时命中时贴的贴纸。
**点开一天能看到那天的全部**：事件、清单（能直接勾、能就地加）、花销、随笔。
月份下面一行小结：写了几天、清单多少、花了多少 —— 当月只算到今天为止，
把还没到的日子算进完成率会永远像落下了一堆。

**倒计时。** 每条记一件事：名字、日期、按阳历还是农历过、标签、提前几天提醒。
**农历不抄万年历表** —— 浏览器内置了中国农历（`Intl` 的 `chinese` 历法），
直接问它"这天农历是几月几"，比手抄两百年的数据可靠。

**账本。** 只记支出。表单只有三格 —— 记账最大的敌人是麻烦，多一步选择
就会有一天懒得记，断一次就断了。

**清单。** 按天看，打钩划去。顶上一排日期球，**滑到正中间的那颗就是当天**。
条目分"每天"和"只此一天"，完成状态按「哪一天 + 哪一条」记 ——
所以今天勾掉的每日事项，明天会重新站在那里等你。

板块之间只通过两样东西打交道：**共享的判断函数**（某天是不是这条日子、
某天该做什么）和**自定义事件**（`dock:dates`、`dock:todo`）。谁改了数据
就喊一声，另一块重读。同一件事的规则只写一份，两处各写一遍迟早会对不上。

## 到期提醒

网页自己数不了日子 —— 页面一关，JS 就不跑了。所以提醒只能由服务器发。
两条路，选一条填进配置就行：

1. **已经有会响的东西**（Bark、机器人、自己在扫的提醒表）→ 填 `queueApi`。
   前端把未来一年该响的时刻整批算好交过去，那头只当一个闹钟队列。
   **农历留在前端算**，服务器什么都不用懂。
2. **什么都没有，从零搭** → 填 `pushApi` + `pushKey`，走 Web Push。
   接口约定见 [push.md](push.md)。

两条都没配的话，倒计时里那几个"提前几天"只是存着，界面上会明说这一点，
也不会请求通知权限 —— **公开版 clone 下来不该一进来就问"允许通知吗"**。

iOS 两条硬规矩：只有**加到主屏**的那份收得到推送，Safari 标签页里不行；
权限必须在一次**真实点击**里请求，页面自己弹的会被直接拒且不再问第二次。

## PWA

- **iOS 只能从 Safari 安装**，而且只认 `apple-mobile-web-app-*` 那几个 meta。
  iOS 上的 Chrome 装不了 PWA。
- **主屏图标不能透明** —— 系统不补白，透明处会变黑。仓库里那几张都压了底色。
- **可遮罩图标要留约 20% 边距**，安卓会按各家形状去切。
- **`manifest.json` 而不是 `.webmanifest`** —— 后者常被服务器当成
  `application/octet-stream` 发出去，用前者省得改服务器配置。
- **改了 service worker 就要动它的 `VERSION`**，否则浏览器认不出有新版本。
- 缓存策略：**只有"同一个网址内容永远不变"的东西才缓存优先**（图、字体）。
  代码文件名不带哈希，必须走网络优先，否则新页面配旧逻辑。
  `/api/` 一律不缓存 —— 没登录时它返回的是跳转，缓存下来等于把登录墙焊死。

### 版本号

代码文件靠地址后面的 `?v=NN` 换版本。**改版本号要连模块之间互相引用的
那些地址一起改** —— 只改 `index.html` 的话，首页拿到新的，但模块内部
`import ... from './fab.js?v=42'` 没变，缓存优先的 worker 继续发旧文件。
这个坑踩过三次。
